# 컴포넌트 계층 패턴

화면을 7층으로 가른다. 각 층은 자기보다 아래만 참조하고, 뷰는 조합만 한다. 층은 접두사로 드러낸다.

설계 근거: [design/component.md](../../design/component.md) · 화면: [design/web.md](../../design/web.md) · 스택 제약: [design/stack.md](../../design/stack.md)

---

## 이 문서

| 섹션 | 핵심 규칙 |
|------|----------|
| **층과 접두사** | 이름이 층을 드러낸다 — 접두사 없이 선언 금지 |
| **참조 방향** | 아래로만. 같은 층·위 층 참조 금지 |
| **바깥 여백** | 요소·블록은 자기 안쪽만. 간격은 담는 쪽이 정한다 |
| **뷰** | 배치만. 시각 속성 선언 금지 |
| **파일** | 컴포넌트 하나 = 파일 하나. 폴더 이름이 층 |
| **마크업** | 반복 마크업은 `<template>` 하나로. 뷰가 복제하지 않는다 |

---

## 층과 접두사

| 층 | 접두사 | 무엇 |
|---|---|---|
| 원시 토큰 | `--x-` | 값 그 자체 |
| 시맨틱 토큰 | `--` | 역할 이름 |
| 요소 | `.e-` | 단일 요소의 최소 스타일 |
| 블록 | `.b-` | 요소 몇 개 + 배치 |
| 구획 | `.s-` | 화면의 한 구역 |
| 뷰 | `.v-` | 구획의 배치 |
| 셸 | 없음 | 뷰 전환만 |

접두사 없는 클래스를 만들지 않는다. 층을 이름에서 못 읽으면 규칙이 검사 대상이 아니다.

컴포넌트 하나 = 파일 하나. 층 이름이 폴더 이름이다.

```
app.css          @layer 선언 + @import 만
x/               원시 토큰
token/           시맨틱 토큰
element/  block/  section/  view/
```

`app.css`가 `@layer`로 순서를 선언하고 `@import ... layer(층)`으로 각 파일을 그 층에 넣는다. 파일은 자기 층을 모른다 — 층은 import 하는 쪽이 정한다.

선언 순서가 캐스케이드 우선순위를 고정하므로, 층을 어겨도 예측 가능하게 진다.

---

## 참조 방향

아래로만 참조한다.

| 층 | 참조 가능 |
|---|---|
| 시맨틱 토큰 | 원시 토큰 |
| 요소 | 시맨틱 토큰 |
| 블록 | 시맨틱 토큰, 요소 |
| 구획 | 시맨틱 토큰, 요소, 블록 |
| 뷰 | 구획, 시맨틱 토큰 |

시맨틱 토큰만이 원시 토큰을 참조한다. 컴포넌트가 팔레트를 직접 보면 이름이 뜻을 잃고, 대비 조정이 전 파일 훑기가 된다.

```css
/* bad: 컴포넌트가 팔레트를 직접 참조 */
.e-badge { background: var(--x-teal-500); }

/* good: 역할 이름을 경유 */
.e-badge { background: var(--accent); }
```

---

## 바깥 여백

요소와 블록은 자기 안쪽만 책임진다. `margin`·`position`·`top`류를 선언하지 않는다.

같은 버튼이 두 곳에서 다른 간격을 갖는 것이 정상이고, 그 차이를 버튼이 알면 안 된다.

```css
/* bad: 요소가 바깥 간격을 안다 */
.e-btn { padding: 10px 16px; margin-top: 12px; }

/* good: 간격은 담는 쪽이 gap 으로 */
.e-btn { padding: 10px 16px; }
.b-form-row { display: flex; gap: var(--gap); }
```

---

## 뷰

뷰는 배치만 한다 — `display`·`grid`·`flex`·`gap`·`order`. 간격 토큰은 배치이므로 참조해도 된다.

색·폰트·곡률·그림자를 한 줄이라도 선언하면 그 순간 뷰가 컴포넌트가 된다. 필요하면 구획으로 내린다.

---

## 마크업

두 곳 이상에 나오는 마크업은 `<template>` 하나로 두고 복제한다. 복제된 마크업은 컴포넌트가 아니다.

템플릿 안에서도 층 규칙이 그대로 간다 — `b-` 템플릿은 `e-`까지만, `s-` 템플릿은 `b-`까지만 품는다.

커스텀 엘리먼트·템플릿 엔진을 쓰지 않는다. 전자는 등록·생명주기가 늘고 후자는 빌드 스텝이다.

---

## 안티패턴

- 유틸리티 클래스(`.mt-4`, `.text-sm`) 추가 → 층을 우회하는 구멍. 간격은 담는 쪽 `gap`, 타이포는 요소 층
- 뷰 선택자에 색 한 줄 → 구획 층으로 내린다
- 요소에 `margin` → 담는 블록의 `gap`
- 컴포넌트가 `--x-` 직접 참조 → 시맨틱 토큰을 하나 만들어 경유
- 뷰마다 같은 마크업 반복 → `<template>` + 복제
- 한 파일에 여러 컴포넌트 → 컴포넌트당 파일 하나, 폴더가 층
- 컴포넌트 파일이 자기 `@layer`를 선언 → `app.css`의 `@import ... layer()` 가 정한다
- 소비자 없는 토큰 그룹 선언 → 쓸 곳이 생길 때 추가
