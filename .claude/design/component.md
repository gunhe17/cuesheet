# 컴포넌트 계층 설계

화면을 계층으로 가른다. 각 계층은 자기보다 아래만 가져다 쓰고, 뷰는 조합만 한다.

화면 결정은 [web.md](web.md), 스택 제약은 [stack.md](stack.md) — 빌드 스텝·프레임워크가 없다는 것이 이 설계의 전제다.

---

## 계층

| 층 | 이름 | 무엇 | 예 |
|---|---|---|---|
| L0 | 원시 토큰 | 값 그 자체 | 팔레트, 폰트 스케일, 간격 스케일, 곡률, 기울기 |
| L1 | 시맨틱 토큰 | 역할 이름 | `surface`, `text-dim`, `accent`, `radius-card` |
| L2 | 요소 | 단일 HTML 요소의 최소 스타일 | 버튼, 인풋, 배지, 시각 텍스트 |
| L3 | 블록 | 요소 몇 개 + 배치 | 폼 행, 큐 블록, 카운트다운, 레일 세그먼트 |
| L4 | 구획 | 화면의 한 구역 | 상단 바, P0 히어로, 축, 레일, P1 목록 |
| L5 | 뷰 | 구획의 배치 | login, register, pick, run, timeline |
| L6 | 셸 | 뷰 전환 | 앱 루트 |

L0과 L1을 가르는 이유가 이 구조의 핵심이다. 컴포넌트는 L1만 본다 — 팔레트를 직접 보면 이름이 뜻을 잃고, 테마·대비 조정이 전 파일을 훑는 일이 된다.

라이트·다크가 갈리는 곳도 L1 한 곳뿐이다(`token/color.css`). 컴포넌트는 자기가 어느 테마에 있는지 모른다.

---

## 참조 규칙

| 층 | 참조 가능 | 금지 |
|---|---|---|
| L0 | 없음 | 다른 토큰 참조 |
| L1 | L0 | 값 직접 기입 |
| L2 | L1 | L0 직접. 바깥 여백. 위치 지정 |
| L3 | L1, L2 | L0 직접. 바깥 여백 |
| L4 | L1, L2, L3 | L0 직접 |
| L5 | L4, L1(간격만) | 색·폰트·곡률·그림자 선언 |
| L6 | L5 | 스타일 선언 전부 |

두 규칙이 실제로 일을 한다.

**바깥 여백 금지 (L2·L3).** 요소는 자기 안쪽만 책임진다. 사이 간격은 담는 쪽이 정한다 — 같은 버튼이 두 곳에서 다른 간격을 갖는 것이 정상이고, 그 차이를 버튼이 알면 안 된다.

**뷰에 시각 속성 금지 (L5).** 뷰 CSS에 색이 한 줄이라도 들어가면 그 순간 뷰가 컴포넌트가 된다. 뷰는 배치만 한다 — grid·flex·gap·순서.

---

## 이름으로 층을 드러낸다

층을 이름에서 읽을 수 없으면 규칙을 기계가 검사할 수 없다.

| 층 | 표기 | 예 |
|---|---|---|
| L0 | `--x-` | `--x-teal-500`, `--x-space-4`, `--x-radius-3` |
| L1 | `--` | `--surface`, `--text-dim`, `--radius-card` |
| L2 | `.e-` | `.e-btn`, `.e-badge`, `.e-time` |
| L3 | `.b-` | `.b-cue`, `.b-countdown`, `.b-rail-seg` |
| L4 | `.s-` | `.s-axis`, `.s-rail`, `.s-hero` |
| L5 | `.v-` | `.v-run`, `.v-timeline` |

접두사 하나로 "이 선언 블록이 자기보다 위 층을 참조하는가"가 정규식 검사가 된다.

---

## 파일

컴포넌트 하나 = 파일 하나. 폴더 이름이 층 이름이다.

```
app.css          @layer 선언 + @import 만
x/               reset · palette · type · space · radius · duration
token/           color · type · space · radius · duration
element/         title · label · input · action · action-ghost · notice
block/           field
section/         app · brand · form · actions
view/            auth
```

`<link>`를 늘리지 않고 `@import ... layer(층)` 하나로 묶는다. 빌드 스텝 없이 파일을 가르는 유일한 방법이다.

대가는 요청 수다 — 파일 하나당 요청 하나이고 `@import`는 `app.css`를 받은 뒤에야 발견되므로 폭포가 된다. 행사장 회선에서 이것이 문제가 되면 그때 이어붙이는 단계를 넣는다. 파일 경계는 그대로 두고 배포만 바뀐다.

`@layer` 선언 순서가 캐시케이드 우선순위를 고정한다. 아래 층 선택자가 아무리 구체적이어도 위 층을 못 이긴다 — 층을 어겼을 때 화면이 조용히 깨지는 대신 예측 가능하게 진다.

## 마크업은 어디에 사는가

CSS는 클래스로 층이 갈리지만, 마크업은 그대로 두면 뷰마다 복제된다. 복제된 마크업은 컴포넌트가 아니다.

`<template>`을 쓴다. L2~L4 컴포넌트의 마크업을 `index.html` 안에 `<template>`으로 한 번만 두고, `app.js`가 복제해 값을 채운다.

| 방식 | 빌드 | 판정 |
|---|---|---|
| 뷰마다 마크업 반복 | 불필요 | 단일 출처가 없다. 채택 안 함 |
| `<template>` + 복제 | 불필요 | 채택 |
| 커스텀 엘리먼트 | 불필요 | 등록·생명주기가 는다. 지금 규모에 과하다 |
| 템플릿 엔진 | 필요 | 스택과 충돌 |

템플릿 안에서도 층 규칙이 그대로 간다 — `b-` 템플릿은 `e-` 템플릿만 품고, `s-`는 `b-`까지만 품는다.

## 이 화면의 목록

[web.md](web.md)의 화면을 층으로 내린 것.

### L2 요소

버튼, 고스트 버튼, 인풋, 라벨, 오류 문구, 배지(지연·상태), 태그, 체크박스, 구분선, 시각 텍스트(고정폭 숫자), 접힘 화살표

### L3 블록

| 블록 | 담는 것 |
|---|---|
| 폼 행 | 라벨 + 인풋 + 오류 문구 |
| 큐 블록 | 축 위의 한 칸. 제목 + 시간 + 담당 표시 |
| 큐 행 | 목록의 한 줄 |
| 카운트다운 | 시각 텍스트 + 설명 |
| todo 행 | 체크박스 + 지시문 + 비고 |
| 레일 세그먼트 | 큐 하나에 대응하는 색 조각 |
| 접힘 헤더 | 개수 + 화살표 |

### L4 구획

상단 바, P0 히어로, manager 조작부, P1 목록, 축(눈금 + 큐 블록), 레일(세그먼트 + thumb), 연결 상태 푸터

### L5 뷰

login, register, pick, run, timeline

## 시각 언어 — Apple

간격·크기·모양·그림자는 Apple 의 것을 따른다. 색 구성만 우리 것이다.

| | |
|---|---|
| 타이포 | Dynamic Type 스케일 (11·12·13·15·16·17·20·22·28·34) |
| 트래킹 | 큰 글자일수록 좁게 — display −0.03em, body −0.016em, caption 0 |
| 행간 | display 1.07, title 1.2, body 1.47, caption 1.38 |
| 간격 | 8pt 그리드 + 4pt 세분 |
| 탭 타깃 | 최소 44×44 |
| 곡률 | 기본 8, 입력 12, 카드 18, 버튼은 알약 |
| 고도 | 테두리가 아니라 넓고 옅은 그림자 (`0 4px 14px / 8%`) |

## 토큰 그룹

| 그룹 | L0 | L1이 붙이는 이름 |
|---|---|---|
| 색 | Tailwind slate·blue 스케일 | `surface`, `text`, `text-dim`, `accent`, `mine`, `warn` |
| 폰트 | 크기·굵기·자간 스케일 | `title`, `body`, `caption`, `time` |
| 간격 | 4의 배수 스케일 | `gap-tight`, `gap`, `pad-card` |
| 곡률 | 반경 스케일 | `radius-card`, `radius-pill`, `radius-rail` |
| 시간 | 전환 시간 | `fade`, `settle` |

기울기는 토큰으로 두지 않는다. 이 화면에 쓸 곳이 없다 — 쓸 곳이 생기면 그때 `--x-slant-*`로 넣는다. 소비자가 없는 토큰 그룹은 규칙만 늘린다.

색 L1 이름에 `mine`이 있는 것이 의도적이다. [web.md](web.md)가 담당 여부를 색의 주 축으로 삼았으므로, 그것이 역할 이름이 되어야 한다.

## 강제

규칙 자체는 [rules/web/component-layer.md](../rules/web/component-layer.md)가 갖는다 — 파일을 열 때 자동으로 로드된다.

접두사 규칙은 지시만으로 지켜지지 않으므로 훅으로 막는다. 저장소가 이미 쓰는 방식이다([settings.json](../settings.json)).

`.claude/hooks/check_layer.py`는 **아직 없다.** 구현하면 `app.css`와 `index.html`을 읽고 아래를 검사한다.

| 검사 | 어길 때 |
|---|---|
| `@layer` 블록 안 선언이 위 층 접두사를 참조 | 거부 |
| L2·L3 선택자가 바깥 여백 선언 | 거부 |
| L5 선택자가 색·폰트·곡률·그림자 선언 | 거부 |
| L2 이상이 `--x-` 직접 참조 | 거부 |
| 템플릿이 자기보다 위 층 클래스를 품음 | 거부 |

## 이 구조가 지는 비용

솔직히 적어둔다. 뷰 5개짜리 화면에 층 7개는 과하다.

값을 하는 것은 L0/L1 분리와 L5의 시각 속성 금지 두 가지다. 나머지 층은 그 둘을 지키기 위한 정리 정돈에 가깝다.

그래도 채택하는 이유: 이 화면은 어두운 행사장에서 대비를 통째로 조정하게 될 가능성이 높다. 그때 L1 이름 몇 줄만 고치면 끝나는가, 전 파일을 훑는가의 차이가 크다.

## 의도적으로 제외한 것

| 항목 | 이유 | 추가할 시점 |
|---|---|---|
| 커스텀 엘리먼트 | 등록·생명주기가 는다 | 뷰가 열 개를 넘고 컴포넌트가 상태를 가질 때 |
| 유틸리티 클래스 | 층을 우회하는 구멍이 된다 | - |
| CSS 번들 이어붙이기 | 빌드 스텝 | 요청 폭포가 실제로 느려질 때 |
| 컴포넌트 변형(variant) 체계 | 변형이 아직 없다 | 같은 컴포넌트가 세 가지 모습을 가질 때 |

## 남은 결정

1. **컴포넌트 카탈로그 페이지를 둘 것인가.** `cuesheet/web/catalog.html` 하나로 전 층을 늘어놓으면 눈으로 회귀 검사가 된다. 정적 디렉토리라 그대로 서빙되므로 운영에 노출되는 것을 감수할지 정해야 한다.
2. **`app.js`를 층에 맞춰 가를 것인가.** CSS·마크업은 층이 있는데 JS는 없다. 렌더 함수를 컴포넌트 단위로 가르면 대칭이 맞고, 파일 하나에 몰면 짧다.
3. **L1 색 이름을 상태 축까지 늘릴 것인가.** 지금은 `mine` 하나가 담당 축이다. 지남·현재·예정을 명도로만 처리할지, 이름을 줄지.
